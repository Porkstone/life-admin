Supply-chain risk reduction plan

A source-led reduction of the npm trust surface. Package count is used as a practical exposure signal: every direct maintainer, transitive publisher and install-time script is another route into development, CI or deployment. Behaviour risk remains explicit so security improvements do not quietly become product regressions.

Wave 2 / supply-chain controls

Harden how dependencies enter deployment

Package removal reduces exposure; deterministic and reviewable installation controls the packages that must remain.

  • Use committed lockfiles and npm ci in CI/deployment.
  • Evaluate --ignore-scripts as the default install policy.
  • Review lockfile changes as security-sensitive code changes.
  • Triage the React Router advisory before any automatic version change.
Exit gate: deployment succeeds from a clean, immutable install and any required lifecycle scripts are explicitly documented.
Wave 3 / policy-led

Only pursue conditional medium-risk items

Attack-surface reduction must justify the local replacement code and the product behaviour it could disturb.

  • Reassess Autoprefixer against current Chrome and Safari output.
  • Node types only after eliminating/retyping all Node-specific config use.
  • Resend or Lucide only if one-package savings justify local maintenance.
Exit gate: targeted functional and visual tests exist before each replacement.
Strategic track / separate project

Do not mix high-risk rewrites with cleanup

Router, toast, Tailwind or lint removal should each be their own explicitly approved initiative with a dedicated test plan.

  • Establish automated route and UI-state coverage first.
  • Set an objective supply-chain risk reduction and rollback threshold.
  • Use one migration branch and rollback point per subsystem.
Recommendation: retain these packages unless install-graph size becomes more important than maintenance cost.

Verification and acceptance

Dependency removals are complete only when a clean install works and the affected user journeys still behave as before.

Automated gates

npx convex dev --once
npm run build
npm ls --depth=0

Behaviour checklist

  • Local Vite and Convex services start and stop cleanly.
  • Sign-in, sign-out and anonymous/authenticated states render.
  • Dashboard tabs support direct navigation and browser back/forward.
  • Invite links preserve the token and complete their intended flow.
  • Password-reset links validate, redirect and send an email.
  • Success and error toasts remain visible for CRUD operations.
  • Admin search, pagination, role changes and reset actions still work.
  • Desktop and narrow-screen layouts show no visual regression.
  • The post-change lockfile contains no unexpected peer-dependency warnings or duplicate major versions introduced by npm.
